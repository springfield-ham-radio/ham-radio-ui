# APRS receive (Kenwood TM-D710)

The **APRS** tab listens to the built-in TNC on the control-head **COM** jack. Stations, the map, packet fields, and the raw log are the menu 604 monitor. That monitor does not transmit, send TNC commands, upload to APRS-IS, igate, or change radio menus. Leave the radio showing **APRS** for that test. **Messages** and **Position beacon** use a host session on the same jack. See [Host messaging](#host-messaging) and [Position beacon](#position-beacon).

The PC jack on the TX/RX unit is the programming and CAT port. It is a different connector and a different baud menu. The DATA mini-DIN is for an external TNC; its PKS pin keys the transmitter when low. Do not use either jack for this tab.

## What Bryan needs to confirm

- The faceplate is TM-D710A, E, or S, or it is TM-D710G, GA, GE, or GS. A saved radio named only "TM-D710" shows both menu sets.
- The cable is on the operation-panel **COM** jack. That jack is an 8-pin connector: RTS out, CTS in, TXD out, GND, RXD in, and three unused pins (TM-D710A/E PACKET OPERATION, “PC/COM terminal pins”; the G manual lists the same COM pins). The optional PG-5G is the cable from that jack to a 9-pin serial connector. The 2.5 mm 3-conductor plug is the **GPS** jack, not COM. Whether a USB adapter actually wires RTS and CTS is not known from software.
- Menu 604 OUTPUT is ON. The Kenwood default is OFF, so a correct cable still produces no lines until that menu is ON.
- The radio's own APRS beacon schedule is whatever is already programmed. HamBench does not change it. A beacon that is already enabled can still go out on the air.

## Radio settings

HamBench does not change these. Set them on the radio. Under **Preferences → Radios**, edit the saved radio and set **APRS serial port** and **APRS baud**. Those fields are stored separately from the memory port and baud. The same adapter name may be saved for both, because one USB device can be moved between jacks. Only one live session can hold that adapter: Read, Write, and CAT stay blocked while APRS is connected, and APRS will not open an adapter CAT already holds. **Connect (Host)** or **Connect (Monitor only)** opens the saved APRS port. The caret only changes which of those two the button will open. Saving APRS settings does not change the memory port. If that adapter is unplugged, the port stays in the list as saved and not connected, and Connect explains that the memory port was left unchanged.

1. Press **[TNC]** until the display shows **APRS** (not PACKET12 and not blank).
2. Menu **604** OUTPUT = **ON**. This is the switch that copies received APRS traffic and TNC monitor text to the COM jack. Default is OFF.
3. COM baud:
   - A/E/S: menu **528**
   - G/GA/GE/GS: menu **929**
   - Choices are 9600, 19200, 38400, and 57600. Default **9600**. Power-cycle the radio after changing it. The computer side is 8 data bits, 1 stop bit, no parity.
4. Menu **601** INTERNAL TNC: data band on the band that is receiving APRS, packet speed **1200 bps** unless that network is 9600.
5. Leave menu **519** / **920** (PC port) and menu **529** / **930** (packet-mode data band) as they are. They do not select this feed.
6. In HamBench, set that same COM baud and the PG-5G adapter on the saved radio, then **Connect (Host)** or **Connect (Monitor only)**. **Disconnect** in Host mode writes the module KISS exit when the TNC is in KISS, which returns it to command mode, then closes the handle. **Disconnect** in Monitor only closes the handle and writes nothing. Read, Write, and CAT will not take that adapter until then. Changing the APRS and Packet tabs does not open or close the port.

The passive session never writes a payload byte. `KISS ON` and `RESTART` are not sent from Stations. `MON ON` is the PACKET-mode default in the TNC command list and is not sent either. The serial flow control is the module’s `aprs.host.flowControl` when that field is present, for both **Connect (Host)** and **Connect (Monitor only)**. There is no flow-control menu on the APRS tab, the Packet tab, or Preferences. A module that omits the field keeps the previous passive open: flow control off, with RTS and DTR deasserted. That is the setup already confirmed on the air for menu 604.

## What the tab shows

The station list includes every heard station. The map shows only stations whose own position was decoded. A message with no position, a Mic-E ambiguous position, a malformed line, and an unsupported format stay off the map and stay in the raw log. An object or item position is not drawn as the sending station. On host, **My callsign**’s saved or prefilled position beacon also appears on the map as a separate blue marker with an amber ring and the same callsign label; it is not added to the heard list. The map fits the stations once, then leaves pan and zoom alone when later packets arrive. **Fit stations** includes that beacon. Click a station on the map or in the Stations list to open a details card on that pin. Hover does not open it. A background click, Escape, or the close control dismisses the card while the row highlight stays.

Positions exist only for this listening session. Menu 604 OUTPUT copies new packets to the COM jack. It does not dump the radio's station list. The TNC `LIST` and `READ` commands are the packet mailbox, not an APRS station export, and HamBench does not send them.

## Decoded fields

Stations are AX.25 sources. A later packet replaces only fields it actually contains, so a message keeps the last position. An object or item position is labeled as a reported object and does not replace the sender's position. Course is omitted for Mic-E when the decoded course is 0, which the protocol uses for unknown. Weather uses the packet's own units (mph, °F, inches, hPa). Mic-E altitude is meters. Uncompressed `/A=` altitude is feet.

Unsupported or malformed text stays in the raw log with a reason. That includes telemetry, queries, third-party packets, NMEA sentences, Mic-E position ambiguity, the `cmd:` prompt, and anything that is not a one-line TNC2 monitor frame. The log and station list are capped (500 lines, 300 stations) and the lists are virtualized.

Packet format follows [APRS Protocol Reference 1.0.1](https://www.aprs.org/doc/APRS101.PDF). The decoder is in this repository; see [ADR 0014](adr/0014-aprs-receive.md).

## Host messaging

Messages use the same COM jack and the same saved port. They do not use the memory port. The list is one row per callsign, and the SSID stays on it. Opening a row or **New message** does not send. An incoming line shows the APRS addressee. An ack updates that outgoing line. It is not a second bubble and it is not a read receipt. The same TNC connection bar sits on the APRS tab and the Packet tab. **Connect (Host)** opens the host session. **Connect (Monitor only)** opens the passive monitor. The caret changes the mode shown on the button and does not connect. While the port is open, both tabs show one **Disconnect**. Changing tabs does not open or close the port. **Passive monitor** reads menu 604 text and writes nothing. If no new line arrives for a minute, the bar notes that the radio may still be in PACKET/KISS and that Monitor only needs APRS mode with Menu 604 output on. A line or Disconnect hides that note. It does not write. When Host detection stops at No reply, the same kind of note appears if the serial reply included a TNC2 monitor line and no command prompt: the radio looks like it is in APRS mode. On a TM-D710 that note says to press TNC until the display shows PACKET, then retry. Silence, or command text that is not a TNC2 line, uses a weaker sentence that the radio may be in APRS mode. An incomplete KISS frame does not get the note. The note does not write. `aprs.host` may set `aprsModeHint` and `aprsModeLikelyHint`. A TM-D710 host block that omits them still uses those sentences. **Host session** opens that same port and runs one detection pass from the installed module's `aprs.host` block ([ADR 0017](adr/0017-aprs-host-detect.md)). A KISS data frame ends the pass with nothing written. An echo of the last write, and `C0 FF C0`, do not. A prompt already in the open buffer runs the enter steps. Monitor text with no prompt writes the module interrupt once and waits for the prompt. After the interrupt, if `cmd:` has not arrived and the module declares `promptNudge`, those bytes are written once, including when the port is silent. An exact echo of the last write is not a KISS frame; during detection it is command mode and writes that nudge if it has not been sent. `kissExit` is written only when the interrupt and the nudge produced no text. If `kissExit` is not declared, detection stops. A module that does not publish `aprs.host` does not receive the TM-D710 sequence. A TM-D710 module that has not been updated yet still uses the tested sequence: three Ctrl+C, then `KISS ON` after `cmd:`, then `RESTART` after another `cmd:`, and it does not declare `kissExit`. Connect does not send a beacon or a message. After the enter steps, the status is "KISS on, waiting for traffic" until an AX.25 UI frame arrives. **Retry detection** sits on the APRS connection row. **Disconnect** in Host mode writes the module KISS exit once when the session is in KISS (waiting or confirmed), logs that outgoing line, and then closes the port so the TNC returns to command mode. A failed write or a missing port still closes. Command mode does not get that write. Monitor only never writes. Disconnect closes whichever session is open. CAT stays on its own tab. **Station details** is the selected station’s decoded fields. It is not packet mail. A parsed AX.25 UI frame from the host session is decoded with the same APRS rules as a menu 604 line and folded into the Stations list and map. Source, destination, and path come from the AX.25 addresses. A digipeater that has already repeated is marked with a star. A frame that is not a position does not get coordinates. The passive path still reads TNC2 text only. It cannot open the port while the host session holds it. One badge shows the port and the mode together: **Disconnected**, **Connected · Monitor**, or **Connected · Host ·** Detecting, Command, KISS waiting, KISS confirmed, or No reply. The tooltip keeps the mode detail. The badge does not write. **Send** stays off until **My callsign** passes that AX.25 check. The format hint is on that field. **Set My callsign to send** sits by the button and focuses the field. A destination that fails the same check is the callsign failure that adds a Not sent line, and that line names the destination. An empty or invalid My callsign does not add one. **Send** is the transmit choice. It writes a message frame only when this host session has parsed an AX.25 UI frame. A KISS frame that is not a UI frame does not count, and it does not clear a confirmation that a UI frame already gave. `cmd:` outside a KISS frame clears that confirmation and cancels the queue. A message is sent at most 3 times, 15 seconds apart. **Cancel** stops it. **Disconnect** drops the queue, and the next Connect does not send it again. **My callsign** is saved on that radio and filled in again after a tab change or a restart. Only a callsign of 3 to 6 characters, starting with a letter, with an SSID from 0 to 15, is written. A half-typed value is not written, and the last saved callsign is what comes back. Clearing the field is saved and the field stays blank. When that radio has no saved callsign, the field starts as the amateur callsign already stored for it under Preferences. That starting value is not written until the field is changed. The Packet SSID is not copied onto it. **Automatically acknowledge messages addressed to my callsign** sits with **My callsign** on the APRS header. It is off each time the port opens, it is not saved, and turning it on does not answer messages already heard. It does not answer an ack, and it is not a read receipt. An ack or reject counts only when it comes from the station you addressed and carries your message number. A carriage return after that ack is the TNC terminator. It is not part of the message number.

Detection listens for a few seconds (`listenMs`, default 3). The command list says one Ctrl+C returns from Converse, and three return from Transparent. It does not say Ctrl+C prints a new `cmd:` when the TNC is already in command mode. `SENDPAC` defaults to carriage return (`$0D`), which sends a packet in Converse, so no newline is written to ask for a prompt. `cmd` without the colon does not count. A prompt that arrives starts the enter steps. Command text after a closed KISS frame is counted as command text, not as an open frame. A data frame that never closes is dropped after one second. `cmd:` after a confirmed UI frame starts detection again. Retry detection clears that decoder first. The A/E and G command lists do not include `CMDTIME`. Three Ctrl+C are written together. `ECHO` defaults to ON. `MONITOR` defaults to ON. `MCON` defaults to OFF and applies while connected, not as a Converse switch. Monitor text that never shows the prompt writes the interrupt once. If `cmd:` still has not arrived and `promptNudge` is set, those bytes go out once, including on a silent port. If command text was seen and the prompt still does not arrive, detection stops, does not send `kissExit`, and does not say the radio may not be in PACKET mode. That sentence is only for a port that sent nothing. Silence writes the interrupt once, then `promptNudge` when the module declares it. Five seconds with no text after those steps writes `kissExit` once when the module declares it, and otherwise writes nothing more. The reply log records each write after `write_binary` returns the same length. Plugin 3.0.9’s `write_all` stops at the kernel `write()` and does not call `tcdrain`, so that count is not an echo. A plugin error is logged and the next step does not start. An `?EH` answer stops the enter steps. KISS-framed bytes are not a prompt and do not get a carriage return. The D710 fallback does not send `C0 FF C0`. `RESET` is not sent.

Menus 600–612 do not control the TNC after KISS is entered. The radio’s station list and beacon are not promised to keep running, and HamBench does not erase them. Menu 604 is not a message input. Menu 602 is GPS or weather. `HBAUD` 1200 is the usual RF speed and is not menu 528 or 929.

The IDM (printed page 27, PDF page 31) says STA and CON blink together six times during the change into KISS. That is not a light that stays on. In the A/E PACKET indicator list, a steady STA means packets remain in the buffer and a steady CON means the TNC is connected. Dark indicators do not mean KISS is off, and a photo of PACKET12 does not prove KISS is on or off.

The A/E command list says, for KISS: “When ON, switching the power OFF then ON causes the TNC to enter (or exit) KISS mode.” The parameter default is OFF. The G command list says: “When ON, entering a RESTART command causes the TNC to enter (or exit) KISS mode.” `RESTART` on both “causes the TNC to function as if it is switched OFF then ON.” The stored ON/OFF parameter is what survives the power switch. Neither sentence says the result alternates, and neither promises that a power cycle leaves KISS. A power cycle can show the startup banner. That observation is not a guaranteed exit. `RESTART` is command text, so it is not available while the TNC is already inside KISS. The A/E packet chapter says press **[TNC]** twice to enter PACKET mode. It does not say that key leaves KISS. HamBench does not power-cycle the radio and does not send `KISS OFF`. Silence after the listen window writes the module interrupt once. If the prompt does not arrive and the module declares `promptNudge`, those bytes are written once before `kissExit`. A carriage return is not sent unless that declaration is present. The TM-D700 bytes `C0 FF C0` are not in the D710 fallback: the IDM says D700 PC commands are not compatible with the D710. They are written only when the module declares `kissExit`.

To leave KISS, **Disconnect** while the badge says KISS. That writes the module KISS exit once and returns the TNC to command mode, then closes the port. If the write fails, the port still closes. Monitor only and command mode do not get that write. HamBench does not send `KISS OFF`. On the radio, switch power OFF, then ON, only when that exit is not available. HamBench does not send a carriage return or Ctrl+C to find the mode. Connect the host session again, and do not press **Send**. A startup banner can include `cmd:`. That line is not proof the TNC left KISS, and it is not proof of PACKET mode. An AX.25 UI line means a KISS payload parsed. A KISS frame that is not a UI frame leaves the mode unconfirmed, and **Send** stays blocked. HamBench does not send `KISS OFF`.

**Raw log** is an APRS sub-tab under **Preferences → Developer → Raw log**, off by default. Both lists keep filling while the sub-tab is hidden; turn the switch on to read what was already captured (within the usual caps). **Serial reply** is the host-session byte log: time, direction, hex, and escaped text. **Clear serial reply** removes those lines and keeps the counters. It does not disconnect or write. **Decoded lines** are the passive menu 604 text and the KISS UI frames already folded into the station list. **Clear decoded lines** also clears that station list and does not write. Command text, an incomplete KISS frame, a bad escape, and a parsed AX.25 UI frame are counted separately. Both lists stay when you change tabs. **Stations** lists what arrived this session. The selected station’s decoded fields sit beside that list, and above it when the pane is narrow. Map uses the same selection for the row highlight and the orange marker; the map details card opens only when you choose that station on the map or in the list, not from the automatic first row. Those fields are not a second copy of either log and not a mailbox. The radio’s stored mailbox is not read. KISS stays unconfirmed until an AX.25 UI frame is parsed. The host listener keeps bytes that arrive as the port opens. The passive monitor still drops its opening fraction of a second, which is the path already verified. Software flow control can take 0x11 and 0x13 before they are listed. That is a capture limit, not a conclusion about the two bytes seen on the air.

## Position beacon

**Position beacon** sits on the host row under **My callsign**. The inline row summarizes position, symbol, path, comment, and last send, with **Beacon now**, an interval switch, and **Edit beacon** for the full form in a modal. With no saved position on this radio, latitude and longitude start from the selected station antenna location (`From <station>` until you save). KISS stops the radio’s built-in beacon schedule, but HamBench can send one uncompressed `=` report from the manual position you save on this radio. **Beacon now** keys the transmitter once when the session has parsed an AX.25 UI frame, the same gate as **Send**. There is no retry. **Connect** does not beacon. An optional interval is off each time the port opens; turning it on starts a timer on this connection only, with a minimum of 10 minutes and a default of 30. **Disconnect**, KISS exit, and loss of that UI confirmation stop the interval. SmartBeaconing is not used. The radio position is not read over CAT while KISS is on; enter latitude and longitude as degrees, minutes, and seconds in the modal. Symbol, comment, optional altitude in feet, and digipeater path (`WIDE1-1,WIDE2-1` by default, at most two hops) are saved per radio. Destination tocall is experimental `APZHMB`. Message frames still use generic `APRS` with no digipeaters. A successful beacon appears on the serial reply log, in decoded lines, and in Stations and Map for your callsign. See [ADR 0027](adr/0027-aprs-position-beacon.md).

## Packet tab

**Packet** uses the same host KISS session as Messages. It does not open a second COM port and it does not add TNC commands. The Packet tab shows the same connection bar as APRS. There is no separate KISS connect button and no flow-control menu. **Connect (Host)** and **Connect (Monitor only)** open the port with the flow control declared by `aprs.host.flowControl`. When that field is absent, Host on a TM-D710 uses hardware RTS/CTS, because `defaultFlow: "software"` on Kenwood 1.15.1 is only the old menu default and KISS receive on this COM jack was verified with RTS/CTS. Host on any other module uses software flow. Monitor only stays off until the module declares a value. A choice saved by the old menu is deleted and is not applied. Detection runs, and no AX.25 frame is sent. **Monitor only** reads APRS text. The Packet tab then says that Packet needs Host mode. The monitor lists every AX.25 frame on that session, not only APRS UI. **Call station** on the terminal sends SABM to the station you typed, shows each attempt while T1 retries up to N2, and warns that each attempt keys the radio. A line sends I frames with a carriage return. RR, retries, the idle poll, and DISC go out only while that link is up. Leaving the tab sends DISC and stops the timers. **Accept incoming connections** is off until you turn it on. While it is off, a SABM addressed to you is ignored and no DM is sent. When it is on, the card answers with UA without pressing **Call station**. **SSID** and **Accept incoming** are saved per radio. The callsign base is the one already stored for this operator. See [ADR 0018](adr/0018-packet-tab.md).

`XFLOW` defaults to ON in the command list. HamBench does not send `XFLOW`, and it does not offer a flow-control menu. The installed module declares the COM-jack setting as `aprs.host.flowControl`: `hardware` (RTS/CTS), `software` (XON/XOFF), or `none`. Kenwood 1.16.0 sets `hardware` on the TM-D710A. The connection line shows that value as text. `flows`, `defaultFlow`, and `flowHelp` may still be in the module so an older HamBench build can read them. This build does not use them to open the port. Kenwood 1.15.1 has no `flowControl` and sets `defaultFlow` to `software`. That software value is the old menu default, not the RTS/CTS setting verified for KISS on this jack, so a TM-D710 host open without the field uses hardware. Monitor only on that older module stays off. Any other module without the field uses software for Host and off for Monitor only. Plugin `FlowControl::Hardware` is serialport `CRTSCTS`: the driver asserts RTS while it can receive and pauses TX when CTS drops. That mode does not ioctl RTS. Forcing RTS low would hold the panel MPU `PCCTS` inhibit. Software and off keep RTS and DTR low. A terminal “RTS on” checkbox is a manual line, not `CRTSCTS`. None of the three sends a byte on connect.

The TM-D710A/E service manual, panel MPU table on printed pages 6–7, names pin 98 `PCCTS` as the UART inhibiting input from the PC and pin 99 `PCRTS` as the UART inhibiting output to the PC. Pins 46 and 47, `TNCCTS` and `TNCRTS`, are the separate inhibit pair toward the TNC. Forcing RTS low holds `PCCTS` in the inhibit state. DTR is not a pin on the COM jack.

`HBAUD    was 1200` is the TNC’s own parameter reply. The command list’s name is `HBAUD` / `HB`, default 1200. A D710 power-on transcript runs `HB 1200` and then prints that line and `cmd:`. Those startup lines are not a fresh prompt by themselves. Host entry waits until that script goes quiet and a bare `cmd:` arrives. HamBench never sends `HB` or `HBAUD`. Plugin `open` writes no payload. `ECHO` defaults to ON, so a command the TNC accepted is echoed. `KISS ON` is a parameter; the A/E text enters KISS on the next power cycle, and the G text enters it on `RESTART`. Neither says the TNC goes silent at `KISS ON` itself.

The TNC has 4 kB of KISS buffer. A partial frame longer than that is dropped. Message text is at most 67 characters. See [ADR 0015](adr/0015-aprs-host-messaging.md).

## Kiss-only host (for example Kenwood TH-D74)

Some radios declare `aprs.mode` `kiss` and `aprs.host.entry` `manual`. They use the same USB port as clone and CAT, not a separate COM jack. Turn KISS on at the radio before **Connect (Host)**. HamBench writes nothing on Connect; KISS is confirmed when an AX.25 UI frame arrives. **Monitor only** is not offered. **Disconnect** writes the module `kissExit` once (for the D74, `C0 FF C0`) and releases the port so CAT and Read can open it again. When **APRS serial port** is left empty, Connect uses the saved memory/CAT port at the profile **APRS baud**; you can still save a different adapter to override that default. See [ADR 0025](adr/0025-aprs-kiss-only-host.md).
