# APRS receive (Kenwood TM-D710)

The **APRS** tab listens to the built-in TNC on the control-head **COM** jack. Stations, the map, packet fields, and the raw log are the menu 604 monitor. That monitor does not transmit, send TNC commands, upload to APRS-IS, igate, beacon, or change radio menus. Leave the radio showing **APRS** for that test. **Messages** is a separate host session on the same jack. See [Host messaging](#host-messaging).

The PC jack on the TX/RX unit is the programming and CAT port. It is a different connector and a different baud menu. The DATA mini-DIN is for an external TNC; its PKS pin keys the transmitter when low. Do not use either jack for this tab.

## What Bryan needs to confirm

- The faceplate is TM-D710A, E, or S, or it is TM-D710G, GA, GE, or GS. A saved radio named only "TM-D710" shows both menu sets.
- The cable is on the operation-panel **COM** jack. That jack is an 8-pin connector: RTS out, CTS in, TXD out, GND, RXD in, and three unused pins (TM-D710A/E PACKET OPERATION, “PC/COM terminal pins”; the G manual lists the same COM pins). The optional PG-5G is the cable from that jack to a 9-pin serial connector. The 2.5 mm 3-conductor plug is the **GPS** jack, not COM. Whether a USB adapter actually wires RTS and CTS is not known from software.
- Menu 604 OUTPUT is ON. The Kenwood default is OFF, so a correct cable still produces no lines until that menu is ON.
- The radio's own APRS beacon schedule is whatever is already programmed. HamBench does not change it. A beacon that is already enabled can still go out on the air.

## Radio settings

HamBench does not change these. Set them on the radio. Under **Preferences → Radios**, edit the saved radio and set **APRS serial port** and **APRS baud**. Those fields are stored separately from the memory port and baud. The same adapter name may be saved for both, because one USB device can be moved between jacks. Only one live session can hold that adapter: Read, Write, and CAT stay blocked while APRS is connected, and APRS will not open an adapter CAT already holds. **Connect** opens the saved APRS port. Saving APRS settings does not change the memory port. If that adapter is unplugged, the port stays in the list as saved and not connected, and Connect explains that the memory port was left unchanged.

1. Press **[TNC]** until the display shows **APRS** (not PACKET12 and not blank).
2. Menu **604** OUTPUT = **ON**. This is the switch that copies received APRS traffic and TNC monitor text to the COM jack. Default is OFF.
3. COM baud:
   - A/E/S: menu **528**
   - G/GA/GE/GS: menu **929**
   - Choices are 9600, 19200, 38400, and 57600. Default **9600**. Power-cycle the radio after changing it. The computer side is 8 data bits, 1 stop bit, no parity.
4. Menu **601** INTERNAL TNC: data band on the band that is receiving APRS, packet speed **1200 bps** unless that network is 9600.
5. Leave menu **519** / **920** (PC port) and menu **529** / **930** (packet-mode data band) as they are. They do not select this feed.
6. In HamBench, set that same COM baud and the PG-5G adapter on the saved radio, then **Connect**. **Disconnect** closes the handle. Read, Write, and CAT will not take that adapter until then.

The passive session writes RTS and DTR deasserted and leaves flow control off. That is the setup already confirmed on the air. It never writes a payload byte. `KISS ON` and `RESTART` are not sent from Stations. `MON ON` is the PACKET-mode default in the TNC command list and is not sent either.

## What the tab shows

The station list includes every heard station. The map shows only stations whose own position was decoded. A message with no position, a Mic-E ambiguous position, a malformed line, and an unsupported format stay off the map and stay in the raw log. An object or item position is not drawn as the sending station. The map fits the stations once, then leaves pan and zoom alone when later packets arrive. **Fit stations** fits them again.

Positions exist only for this listening session. Menu 604 OUTPUT copies new packets to the COM jack. It does not dump the radio's station list. The TNC `LIST` and `READ` commands are the packet mailbox, not an APRS station export, and HamBench does not send them.

## Decoded fields

Stations are AX.25 sources. A later packet replaces only fields it actually contains, so a message keeps the last position. An object or item position is labeled as a reported object and does not replace the sender's position. Course is omitted for Mic-E when the decoded course is 0, which the protocol uses for unknown. Weather uses the packet's own units (mph, °F, inches, hPa). Mic-E altitude is meters. Uncompressed `/A=` altitude is feet.

Unsupported or malformed text stays in the raw log with a reason. That includes telemetry, queries, third-party packets, NMEA sentences, Mic-E position ambiguity, the `cmd:` prompt, and anything that is not a one-line TNC2 monitor frame. The log and station list are capped (500 lines, 300 stations) and the lists are virtualized.

Packet format follows [APRS Protocol Reference 1.0.1](https://www.aprs.org/doc/APRS101.PDF). The decoder is in this repository; see [ADR 0014](adr/0014-aprs-receive.md).

## Host messaging

Messages use the same COM jack and the same saved port. They do not use the memory port. The list is one row per callsign, and the SSID stays on it. Opening a row or **New message** does not send. An incoming line shows the APRS addressee. An ack updates that outgoing line. It is not a second bubble and it is not a read receipt. One **APRS COM** control sits above Stations, Map, Messages, and Raw log. **Passive monitor** reads menu 604 text and writes nothing. **Host session** opens that same port and runs one detection pass from the installed module's `aprs.host` block ([ADR 0017](adr/0017-aprs-host-detect.md)). A KISS data frame ends the pass with nothing written. An echo of the last write, and `C0 FF C0`, do not. A prompt already in the open buffer runs the enter steps. Monitor text with no prompt writes the module interrupt once and waits for the prompt. After the interrupt, if `cmd:` has not arrived and the module declares `promptNudge`, those bytes are written once, including when the port is silent. An exact echo of the last write is not a KISS frame; during detection it is command mode and writes that nudge if it has not been sent. `kissExit` is written only when the interrupt and the nudge produced no text. If `kissExit` is not declared, detection stops. A module that does not publish `aprs.host` does not receive the TM-D710 sequence. A TM-D710 module that has not been updated yet still uses the tested sequence: three Ctrl+C, then `KISS ON` after `cmd:`, then `RESTART` after another `cmd:`, and it does not declare `kissExit`. Connect does not send a beacon or a message. After the enter steps, the status is "KISS on, waiting for traffic" until an AX.25 UI frame arrives. **Retry detection** sits on the APRS connection row. Disconnect closes whichever of the two sessions is open. CAT stays on its own tab. **Station details** is the selected station’s decoded fields. It is not packet mail. A parsed AX.25 UI frame from the host session is decoded with the same APRS rules as a menu 604 line and folded into the Stations list and map. Source, destination, and path come from the AX.25 addresses. A digipeater that has already repeated is marked with a star. A frame that is not a position does not get coordinates. The passive path still reads TNC2 text only. It cannot open the port while the host session holds it. The badge says **Connected** or **Disconnected**. KISS confirmation is a sentence on that same connection, not a second badge. **Send** is the transmit choice. It writes a message frame only when this host session has parsed an AX.25 UI frame. A KISS frame that is not a UI frame does not count, and it does not clear a confirmation that a UI frame already gave. `cmd:` outside a KISS frame clears that confirmation and cancels the queue. A message is sent at most 3 times, 15 seconds apart. **Cancel** stops it. **Disconnect** drops the queue, and the next Connect does not send it again. **Automatically acknowledge messages addressed to my callsign** sits with **My callsign** on the APRS header. It is off each time the port opens, it is not saved, and turning it on does not answer messages already heard. It does not answer an ack, and it is not a read receipt. An ack or reject counts only when it comes from the station you addressed and carries your message number. A carriage return after that ack is the TNC terminator. It is not part of the message number.

Detection listens for a few seconds (`listenMs`, default 3). The command list says one Ctrl+C returns from Converse, and three return from Transparent. It does not say Ctrl+C prints a new `cmd:` when the TNC is already in command mode. `SENDPAC` defaults to carriage return (`$0D`), which sends a packet in Converse, so no newline is written to ask for a prompt. `cmd` without the colon does not count. A prompt that arrives starts the enter steps. Command text after a closed KISS frame is counted as command text, not as an open frame. A data frame that never closes is dropped after one second. `cmd:` after a confirmed UI frame starts detection again. Retry detection clears that decoder first. The A/E and G command lists do not include `CMDTIME`. Three Ctrl+C are written together. `ECHO` defaults to ON. `MONITOR` defaults to ON. `MCON` defaults to OFF and applies while connected, not as a Converse switch. Monitor text that never shows the prompt writes the interrupt once. If `cmd:` still has not arrived and `promptNudge` is set, those bytes go out once, including on a silent port. If command text was seen and the prompt still does not arrive, detection stops, does not send `kissExit`, and does not say the radio may not be in PACKET mode. That sentence is only for a port that sent nothing. Silence writes the interrupt once, then `promptNudge` when the module declares it. Five seconds with no text after those steps writes `kissExit` once when the module declares it, and otherwise writes nothing more. The reply log records each write after `write_binary` returns the same length. Plugin 3.0.9’s `write_all` stops at the kernel `write()` and does not call `tcdrain`, so that count is not an echo. A plugin error is logged and the next step does not start. An `?EH` answer stops the enter steps. KISS-framed bytes are not a prompt and do not get a carriage return. The D710 fallback does not send `C0 FF C0`. `RESET` is not sent.

Menus 600–612 do not control the TNC after KISS is entered. The radio’s station list and beacon are not promised to keep running, and HamBench does not erase them. Menu 604 is not a message input. Menu 602 is GPS or weather. `HBAUD` 1200 is the usual RF speed and is not menu 528 or 929.

The IDM (printed page 27, PDF page 31) says STA and CON blink together six times during the change into KISS. That is not a light that stays on. In the A/E PACKET indicator list, a steady STA means packets remain in the buffer and a steady CON means the TNC is connected. Dark indicators do not mean KISS is off, and a photo of PACKET12 does not prove KISS is on or off.

The A/E command list says, for KISS: “When ON, switching the power OFF then ON causes the TNC to enter (or exit) KISS mode.” The parameter default is OFF. The G command list says: “When ON, entering a RESTART command causes the TNC to enter (or exit) KISS mode.” `RESTART` on both “causes the TNC to function as if it is switched OFF then ON.” The stored ON/OFF parameter is what survives the power switch. Neither sentence says the result alternates, and neither promises that a power cycle leaves KISS. A power cycle can show the startup banner. That observation is not a guaranteed exit. `RESTART` is command text, so it is not available while the TNC is already inside KISS. The A/E packet chapter says press **[TNC]** twice to enter PACKET mode. It does not say that key leaves KISS. HamBench does not power-cycle the radio and does not send `KISS OFF`. Silence after the listen window writes the module interrupt once. If the prompt does not arrive and the module declares `promptNudge`, those bytes are written once before `kissExit`. A carriage return is not sent unless that declaration is present. The TM-D700 bytes `C0 FF C0` are not in the D710 fallback: the IDM says D700 PC commands are not compatible with the D710. They are written only when the module declares `kissExit`.

To leave an unknown TNC state without the computer sending a payload: **Disconnect**. On the radio, switch power OFF, then ON. HamBench does not send a carriage return or Ctrl+C to find the mode. Connect the host session again, and do not press **Send**. A startup banner can include `cmd:`. That line is not proof the TNC left KISS, and it is not proof of PACKET mode. An AX.25 UI line means a KISS payload parsed. A KISS frame that is not a UI frame leaves the mode unconfirmed, and **Send** stays blocked. HamBench does not send `KISS OFF`.

**Raw log** holds two lists. **Serial reply** is the host-session byte log: time, direction, hex, and escaped text. **Clear serial reply** removes those lines and keeps the counters. It does not disconnect or write. **Decoded lines** are the passive menu 604 text and the KISS UI frames already folded into the station list. **Clear decoded lines** also clears that station list and does not write. Command text, an incomplete KISS frame, a bad escape, and a parsed AX.25 UI frame are counted separately. Both lists stay when you change tabs. **Stations** lists what arrived this session. The selected station’s decoded fields sit beside that list, and above it when the pane is narrow. Map uses the same selection. Those fields are not a second copy of either log and not a mailbox. The radio’s stored mailbox is not read. KISS stays unconfirmed until an AX.25 UI frame is parsed. The host listener keeps bytes that arrive as the port opens. The passive monitor still drops its opening fraction of a second, which is the path already verified. Software flow control can take 0x11 and 0x13 before they are listed. That is a capture limit, not a conclusion about the two bytes seen on the air.

## Packet tab

**Packet** uses the same host KISS session as Messages. It does not open a second COM port and it does not add TNC commands. **Connect KISS** is the shared host Connect and uses the flow control saved for this radio on the APRS host row. When none is saved, it uses the module default. Detection runs, and no AX.25 frame is sent. The monitor lists every AX.25 frame on that session, not only APRS UI. **Connect** on the terminal sends SABM to the station you typed. A line sends I frames with a carriage return. RR, retries, the idle poll, and DISC go out only while that link is up. Leaving the tab sends DISC and stops the timers. **Accept incoming connections** is off until you turn it on. While it is off, a SABM addressed to you is ignored and no DM is sent. The callsign is the one already stored for this operator. See [ADR 0018](adr/0018-packet-tab.md).

`XFLOW` defaults to ON in the command list, which is software flow control. **Flow control** is chosen on the APRS COM row before Connect and is not changed because a log is quiet. **Software (XON/XOFF)** is the default and keeps RTS and DTR low. **Off** is the passive monitor’s setting and also keeps RTS and DTR low. **Hardware (RTS/CTS)** is for a TNC whose display already says `XFLOW OFF`. The plugin’s `FlowControl::Hardware` is serialport `CRTSCTS`: the driver asserts RTS while it can receive and pauses TX when CTS drops. That mode does not ioctl RTS. A terminal “RTS on” checkbox is a manual line, not `CRTSCTS`. None of the three sends `XFLOW`.

The TM-D710A/E service manual, panel MPU table on printed pages 6–7, names pin 98 `PCCTS` as the UART inhibiting input from the PC and pin 99 `PCRTS` as the UART inhibiting output to the PC. Pins 46 and 47, `TNCCTS` and `TNCRTS`, are the separate inhibit pair toward the TNC. Forcing RTS low holds `PCCTS` in the inhibit state. DTR is not a pin on the COM jack.

`HBAUD    was 1200` is the TNC’s own parameter reply. The command list’s name is `HBAUD` / `HB`, default 1200. A D710 power-on transcript runs `HB 1200` and then prints that line and `cmd:`. HamBench never sends `HB` or `HBAUD`. The 17-byte enter string was `\\rKISS ON\\rRESTART\\r`. Plugin `open` writes no payload. `ECHO` defaults to ON, so a command the TNC accepted is echoed. `KISS ON` is a parameter; the A/E text enters KISS on the next power cycle, and the G text enters it on `RESTART`. Neither says the TNC goes silent at `KISS ON` itself.

The TNC has 4 kB of KISS buffer. A partial frame longer than that is dropped. Message text is at most 67 characters. See [ADR 0015](adr/0015-aprs-host-messaging.md).
